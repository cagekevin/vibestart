# ADR-0009 · 约定只走三级阶梯：禁会绕路的闸，不禁只出事实的扫描

- **状态**：生效
- **结论**：结构/类型优先（做不到就让对的路更短），唯一范本其次，文档最后；代码检查只用官方命令。禁的是「判代码对错、据此报错或阻断、且能被换个位置绕过」的扫描闸；只输出事实或参考结论、恒 exit 0、不进检查链的扫描可建。
- **日期**：2026-11-08
- **裁定人**：架构师（取证后自定 · 2026-11-08 按用户裁定制订）
- **触发**：—

> 下文引用的 `src/…`、`scripts/…`、`daily/…` 路径来自原仓 dsh-lovart，**不在本项目里** —— 它们是判据的由来，不是本项目的位置。

## 背景

模板仓库带进了 `scripts/check-any-honesty.mjs`，AGENTS 也沿用了「能做成闸就做成闸」的措辞。上一轮据此又写了 `scripts/check-conventions.mjs`（14 条正则规则）。两次都证明同一件事：扫描式闸会把人引向「让检查通过」，而不是「让错误写不出来」——注释里解释 `throw new Error` 会被误报，真正的结构问题却照样能绕过去。

**但这不等于「凡扫描一律不许」。** 2026-11-08 用户裁定：扫描本身不是问题；问题是把它做成「AI 不这样写就报错」的闸，尤其是靠正则查「某处不许出现 X」——AI 直接换个文件写同样实现即可绕过，闸没拦住，还多一套维护。只输出客观事实（谁引用了谁、真实退出码、残留位置）供人／AI 参考的扫描，可以建。

## 判据（它凭什么成立 / 为什么不成立）

- ADR-0004：能让写错编译不过，就不写文档。扫描闸只是文档的自动朗读版，不是结构。
- 官方检查只有 `tsc --noEmit`、`tsdown`、`node --test`。再写一个判定「合规／不合规」并阻断的源码扫描器，就多一套解析器和一套误报豁免，最后变成第二本账。
- **一条禁令若能被 AI 换个位置写同样实现绕过去，它就是「反向闸」**：价值为负 —— 没让错误写不出来，只教会 AI 绕路。典型：某文件不许出现 `fetch` ⇒ 第二处 `fetch` 写到别的文件；不许用 `process.cwd` ⇒ 换个包装函数照样落。
- 有些东西 TS 确实禁不掉（全局 `fetch`、`console`、`process.cwd`）。对它们，正确答案不是「加扫描」，而是「让第二处没有必要存在」：把 url / 凭据 / 超时收进闭包，把 cwd 解析收进唯一样本。
- 只出事实的扫描不进任何判定链，误报只是多看一眼；它不产生「必须照做」的动作，因此没有绕行激励。

## 决议

**约定落点只有三级，没有第四级：**

1. **写不出来**：类型、判别联合、私有构造、工厂、端口类型、穷尽 `switch` + `never`。能用这一级就只用这一级。
   做不到时，这一级还有另一半：**让正确的路比错误的路更简单** —— 默认值、签名、唯一入口把对的路做成最短的一条；错的路仍能走，但要多写一步（多传一个参数、多一层显式声明、多一个 import）。两者同属一级：都不需要谁先读过什么，也没有范本要找；区别只是前者错的路不存在，后者错的路还在，但要多写一步才走得通。
2. **抄不错**：只保留一个范本文件，AGENTS 只写「照哪个文件抄」。不再写第二份等价说明。
3. **写清楚**：前两级都做不到时才写文字，并注明为什么只能靠文字（通常是 TS 管不到的全局对象或流程）。

**【2026-11-13 补】** 第一级原只写「写不出来」，漏了它更弱的一半：类型挡不住时，让对的路比错的路短。用户裁定补进第一级，不另开第四级 —— 它和「写不出来」一样不依赖读者，区别只是错的路还在，没人会顺脚走过去。

**这条对 ADR 自己也生效（2026-11-09 补）**：每加一条治理规则，先问「它能不能被结构替代」。能 ⇒ 别写规则，去改结构。写不出「为什么它不能做成结构」的规则，一律删 —— 否则这套账本自己就是项目里最大的兜底。

**检查边界：**

- 代码检查只用官方命令：`tsc --noEmit`、`tsdown`、`node --test`。
- ADR / 债务 / 架构索引脚本是流程工具，可以用来检查文档账本，**不得用来判断代码写得对不对**。
- **不建「闸」**：任何判定代码合规、并据此报错 / 非零退出 / 拦提交 / 进 `check` 的扫描脚本，一律不建；尤其是正则写的「某处不许出现 X」禁令。
- **允许「只出事实」的扫描**：只输出客观事实或参考结论，自身恒 `exit 0`、不进 `check`、不接提交钩子、不要求 AI 照做。`check-any-honesty.mjs` 与 `check-conventions.mjs` 因为同时满足「判对错 + 阻断 + 可绕过」已删除。
- 显式 `any` 不再靠脚本拦截：外部输入一律 `unknown` 进解析函数，公共签名不留 `any`，范本固定在**唯一的外部输入解析点**（本项目里是哪个，见 `docs/architecture.md` 的「原语」）；平台边界只在唯一桥接点收口。
- 全局 `fetch` 禁不掉：`request.ts` 用闭包持有 baseUrl / 凭据 / 超时，其他模块只拿到 `LovartClient`；新增端点只动 `api.ts`。

**边界补充：出事实 ≠ 机器闸。**

| 工具 | 产出 | 不做什么 |
|---|---|---|
| `probe.mjs` | 负例证据：临时改坏一处 → 跑官方命令 → 断言确实红 → 无条件还原 | 不选测试、不缓存、不拦提交，也不接进 `check` |
| `mv-sync-refs.mjs` | 数据流事实：谁 import 谁、串残留引用在哪、搬移会影响哪些文件 | 不判合规、不出通过/失败结论 |
| `post-check.mjs` | 回执：复述 `tsc --noEmit` 的真实退出码与首屏输出，再打印 AGENTS 的交付四问 | 不判断代码对错，自身恒 exit 0 |

删除 `extract-detours.mjs` / `ts-strict-detail.mjs` 是因为本仓没有它们的消费场景，不是因为它们是闸。

**【2026-11-08 修正留痕】** 原结论写作「自创扫描脚本一律不建」；按用户裁定收窄为「只禁会绕路的闸，不禁只出事实的扫描」。原因：原措辞会把「只输出事实、供人参考」的观察工具一并误杀，而这类工具没有绕行激励。

## 后果

- ✅ 不再维护第二套解析器与豁免名单；检查失败只可能来自类型、构建、测试。
- ⚠️ `console`、`process.cwd`、默认导出这些只能靠范本与评审，回潮时不会被自动发现。
- 📌 **违反时的判据**（怎么发现「又回去了」）：新增判定合规并阻断的 `src/` 扫描脚本；新增「某处不许出现 X」的正则禁令；`check` 链出现非官方代码检查；同一状态出现第二个解析函数；`request.ts` 之外出现 baseUrl / 凭据 / 超时；对的路比错的路多写一步（默认值反了、签名逼调用方手写包装）。
