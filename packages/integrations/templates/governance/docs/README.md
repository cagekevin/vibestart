# 文档地图

一份文件只回答一个问题。先看这张表，再决定读哪份 —— 不要从目录第一页开始读。

| 文件 | 回答的问题 | 变化频率 | 真源 | 冲突时谁赢 |
| --- | --- | --- | --- | --- |
| `start.md` | 开局怎么把下面这些定下来（**做完就删**） | 一次 | 人 | — |
| `context.md` | 给谁做、不做什么、词是什么意思 | 慢（产品变了才改） | 人 | 人裁定 |
| `spec/<能力>.md` | 这个能力**对外**怎么表现 | 中（每次改行为） | 人（意图） | 人裁定 |
| `plan/<日期>-<能力>.md` | 这**一次**怎么改：原语 → 契约 → 形状 → 数据流 | 一次（落地即作废） | 人 | spec 赢 |
| `architecture.md` | 现在有哪几个原语、分几层、依赖朝哪、哪条不变量跨模块 | 快（与代码同批） | 描述归代码，不变量归文档 | 描述：代码赢；**不变量：代码输** |
| `adr/` | 为什么这样定、推翻过什么 | 只增不改 | 人（裁定） | ADR 赢，推翻要新 ADR |
| `../daily/架构日志/债务.md` | 知道但还没还的账 | 只增 / 销账 | `scripts/debt.mjs` | — |
| `../AGENTS.md` | 怎么干活：开工读什么、交付前问什么 | 几乎不变 | 人 | — |

`architecture.md` 里有两类内容，冲突时方向相反：**描述**（分几层、依赖朝哪）以代码为准 —— 代码是事实；**不变量**（跨模块约束）以文档为准 —— 代码违反它是 bug，不是文档过期。分不清时按「不变量」处理：宁可停下来问，也不要顺手改文档。

## 读什么

- 第一次进这个仓库：`context.md` → `architecture.md` → `../AGENTS.md`。
- 要改一个能力：`spec/<能力>.md` → 相关 `adr/` → `architecture.md` 的对应段。
- 要动手之前：`plan/README.md` 的骨架，先把这次怎么改写下来。
- 想知道某条约定为什么这样：`adr/README.md` 的索引。
- 想知道哪里欠账：`../daily/架构日志/index.md` → `债务.md`。

## 三条硬规矩

1. **能被类型、测试或目录结构表达的，不写进文档。** 写进去必然过期，而且从此有两个真源。
2. **一份事实只出现在一份文件里。** 第二份出现的那一刻，漂移就开始了 —— 要么删掉一份，要么改成链接。
3. **冲突按上表的「谁赢」处理。** 不许「两边各改一点」：那会留下两份都像现行的文本，下一个人只能赌。
